# 韩语情境闯关 · 项目说明与修改指南

> 一个纯静态的韩语情境学习小游戏。10 个真实生活情境，86 道决策题，
> 像素风场景图 + NPC 立绘，进度条达到 90% 即通关。
> 由《外语大闯关（英语版）》完整迁移而来，题目与台词改为韩语。
> **难度定位：零基础入门**——台词都是 2–6 个词的最高频短句，无复杂语法，完全没学过韩语也能玩。
>
> **换设备使用**：解压后双击 `index.html` 即可玩（无需装任何东西）。
> 要改内容，先读这份 README；改完跑 `python tools/self_check.py` 验收。

---

## 一、怎么跑起来

### 方式 A：双击即玩（零配置，推荐）

直接双击 `index.html`，用浏览器打开就能玩。不需要装任何东西、不需要起服务器。
`file://` 协议下 10 张关卡卡片、场景图、NPC、答题进度、localStorage 存档均正常。

> 存档存在浏览器 localStorage 里，key 前缀为 `kr_lexi_`，与英语版隔离。
> 换浏览器或清缓存会丢进度（属正常）。

### 方式 B：本地起服务器（改代码时用）

```bash
python -m http.server 8765
# 浏览器打开 http://localhost:8765/index.html
```

## 三、修改指南

### A. 改题目（最常做的事）

**唯一数据源是 `韩语情境闯关_方案书.md` 第 4 章，不要直接改 `data/questions.js`**（会被覆盖）。

```
1. 改 韩语情境闯关_方案书.md 第 4 章的题库
2. python tools/build_data.py          ← 重新生成 data/*.js
3. python tools/check_distinctness.py  ← 结构验收
4. 浏览器打开确认
```

**题目格式**（方案书里长这样）：

```markdown
#### DP1 · 店员问你喝什么 | 考点：说要什么（주세요）
> NPC：「안녕하세요! 뭐 드릴까요?」

- **A. 아이스 라떼 주세요.** ✅
- B. 빵 있어요?
- C. 조금만 기다려 주세요.
- D. 저는 지금 바빠요.

**解析**：正确项 `아이스 라떼 주세요` 说出想喝的…（中文解析，用反引号引用韩语短句）
```

**四个选项的构成规则（v3 决策分岔型）**：

| 层次 | 缺陷 | 例子 |
|---|---|---|
| ✅ 正确项 | 完成当前任务 | `아이스 라떼 주세요` |
| L1 | 转移话题——问了另一件事 | `빵 있어요?` |
| L2 | 做别的事——改了需求 | `조금만 기다려 주세요` |
| L3 | 无关回应 / 对陌生人用半语 | `저는 지금 바빠요` |

四条硬规则：意图互斥、场景合法、唯一最优、微差异禁用。
零基础约束：台词 ≤ 8 词、选项 2–6 词，只用最高频句型，不出现复杂语法与长难句。

**解析格式约束**：**不要用字母指代选项**。用反引号包住韩语原文短句指代，
因为 `build_data.py` 会按 `A→C→B→D` 循环重排答案位置，用字母会导致解析错位。

### B. 改情境配置

进度参数在 `tools/build_data.py` 的 `SCENE_META` 里，难度标签从方案书情境标题的「（零基础）」解析。

| 情境类型 | 起始 | 每题增量 | 题数 | 满进度 | 达标线 | 容错 |
|---|---|---|---|---|---|---|
| 普通情境 | 20% | +10% | 8 | 100% | 90% | 1 题 |
| 复杂情境 | 20% | +8% | 10 | 100% | 90% | 1 题 |

复杂情境（10 题）：情境 7 航班延误改签 · 情境 8 求职面试 · 情境 9 会议汇报。

### C. 改界面

全部在 `index.html` 里，纯 HTML + CSS + 原生 JS，零依赖、零 CDN。
- 配色变量在 `:root`；韩语字体链在 `body{font-family:…}`（Apple SD Gothic Neo / Malgun Gothic / Noto Sans KR）
- 存档 key 前缀 `kr_lexi_`；本地点评和 AI 点评均为韩语，中文注解对照
- AI 点评调用语言标记 `lang:"ko"`，未配置云服务时自动降级到本地韩语点评

### D. 改美术

场景图与 NPC 立绘从英语版完整复用，无需重制。
- UI 版场景图可重建：`python tools/make_ui_scenes.py`
- `tools/pixel_scenes.py` 是参考实现，直接覆盖会丢失手工调整，先输出到预览目录对比

## 四、校验清单

### 一键自检

```bash
python tools/self_check.py
```

检查 7 项：file:// 直接玩 · 改题重建链路 · 选项区分度 · UI 场景图重建 ·
场景图生成器 · 资源引用完整性 · GitHub Pages 子路径部署。
输出 `★ 全部通过` 即可发布。首次运行若提示缺 playwright：
`pip install playwright && python -m playwright install chromium`。

> **本次实测**：因本机 Headless Chrome 需特定稳定参数，端到端测试改用 CDP 脚本直接验证，
> 结果为 10 关资源全加载、第 1 关完整通关 100%、零 JS 错误。静态一致性另用 Node 校验通过。

### 分项校验

```bash
python tools/build_data.py          # 方案书 -> data/*.js
python tools/check_distinctness.py  # 结构/选项校验
```

> 注意：`check_distinctness.py` 的分词规则是为英语设计的，对韩语文本的实义词重叠判别力有限，
> 因此其「0 题不通过」在韩语上仅能作为结构层面的参考。韩语干扰项质量需在出题时人工把关
> （意图互斥、用词是否得体），这也是方案书 v3 纪律的核心要求。

## 五、已知限制

| 项 | 说明 |
|---|---|
| 选项区分度检测对韩语判别力有限 | `check_distinctness.py` 按英文空格分词，韩语需人工审校 |
| AI 点评未接真实云服务 | 代码与降级逻辑已写好，需在 WorkBuddy 激活云服务后填 `window.CLOUD_CONFIG`；未配置时走本地韩语点评 |
| NPC 分配有复用 | 9 个角色覆盖 10 个情境（与英语版一致） |
| 解析未做韩语母语者审校 | 脚本保证「引用与选项对得上」，建议找韩语老师过一遍语感 |
| 场景图沿用英语版 | 场景为通用生活场景（咖啡店、机场、会议室等），无英语文字，可安全复用 |

## 六、GitHub Pages 部署

项目已为 GitHub Pages 做好全部准备（`.nojekyll`、`.gitignore`、部署指南）。
所有资源引用均为相对路径，支持子路径部署。

```bash
git init
git branch -M main
git add -A
git commit -m "feat: 韩语情境闯关 · 86 题 · 零基础韩语短句 · 像素风"
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

然后到仓库 **Settings → Pages** → Source 选 **Deploy from a branch** → `main` → `/ (root)` → Save。
访问地址：`https://<用户名>.github.io/<仓库名>/`
详细步骤见 **`GITHUB_PAGES_部署指南.md`**。

## 七、与英语版的关系

- 题库逐题一一对应（10 情境、86 题），语义骨架相同，台词与选项改为韩语。
- 难度定位为零基础入门：台词压到 2–6 词高频短句，无复杂敬语与语法术语。
- 解析保留中文，便于中文母语学习者理解。
- 界面、美术、工具链、进度机制完全复用；存档 key 加 `kr_` 前缀隔离。
